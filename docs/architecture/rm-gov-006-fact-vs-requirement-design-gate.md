# RM-GOV-006 — mini-design: единое правило факта и требования

**Статус:** реализовано, ожидает приёмки владельца
**Задача:** `RM-GOV-006` (этап G, зависит от `RM-GOV-001`)
**Base SHA:** `2b935bb980028a3e67db51718377836bb6242da9`
**Утверждённая приёмка:** approved правило §1.1 записано без конфликта в индекс/ADR-процесс;
targeted doc guard зелёный.

---

## 1. Что записано

`docs/architecture/adr/ADR-020-fact-vs-requirement.md` фиксирует OD-001:

> Код и тесты описывают фактическое поведение. ТЗ и ADR описывают требуемое.
> Расхождение между ними является дефектом до появления явного ADR, который это
> расхождение принимает.

Правило разложено на четыре обязательных следствия, из которых важнейшее —
**расхождение закрывается решением, а не переписыванием**: допустимо привести
поведение к требованию либо принять новое поведение новым/изменяющим ADR, но не
молча привести документ к коду.

## 2. Почему ADR, а не строка в `AGENTS.md`

`AGENTS.md` — контракт работы агентов. Правило о природе требования принадлежит слою
архитектурных решений и должно быть перекрываемо только другим ADR. Альтернатива
«записать в `AGENTS.md`» рассмотрена и отклонена внутри самого ADR-020.

## 3. Совместимость с существующим порядком — проверена, а не заявлена

Правило могло конфликтовать с двумя действующими формулировками:

| Действующее правило | Конфликт? |
|---|---|
| Порядок истины: Git/код/тесты/CI выше архитектурных документов | Нет. Порядок отвечает «чему верить о **факте**»; ADR-020 — «что означает расхождение». Первенство кода в описании факта не делает код источником требования. |
| `ADR Precedence`: ADR побеждает прочие архитектурные документы | Нет. Перечень — design gates, correction plans, phase reports. Код в него не входит: он не конкурирует с ADR за право быть требованием. |

Совпадение заявленного порядка истины проверяется машинно: модуль `doc` извлекает
цепочку из `AGENTS.md` и из `CLAUDE.md` и сравнивает их между собой и с эталоном
ADR-020. Сейчас обе дают
`owner instruction → git → project_state → feature-registry → roadmap → auto-memory`.

## 4. Модуль `doc` гейта

Владелец правила — `RM-GOV-006`; модуль зарегистрирован в единственном entrypoint
`RM-GOV-004`, отдельного CI-job не заводит (правило B-3).

| Проверка | Что ловит |
|---|---|
| `RULE-MISSING` | ADR-020 удалён |
| `ADR-MALFORMED` | нет раздела Context / Decision / Consequences |
| `RULE-NOT-STATED` | ADR ссылается на правило, но не формулирует его |
| `ADR-NOT-ACCEPTED` | статус понижен с ACCEPTED |
| `ORDER-CONFLICT` | `AGENTS.md` и `CLAUDE.md` заявляют разный порядок истины |
| `ORDER-CHANGED` | порядок изменился относительно того, из которого исходит ADR-020 |
| `ORDER-UNREADABLE` | формулировка порядка исчезла — проверка ослепла |
| `ADR-UNINDEXED` | новый ADR вне Active-таблицы и вне объявленных исключений |

Пять tamper-кейсов измерения `doc` в матрице гейта; всего матрица выросла до **20/20**.

## 5. Индексирование не выполнено — намеренно

Приёмка говорит «записано без конфликта в индекс/ADR-процесс». Внести ADR-020 в
индекс Sources of Truth значит отредактировать `AGENTS.md`, а Gate G прямо запрещает
править канонические файлы до cutover. Требование очереди не может обязывать к
действию, которое та же очередь запрещает, поэтому прочтение принято такое:

- правило **записано** (ADR-020 существует, сформулировано, ACCEPTED);
- оно **не конфликтует** с индексом и ADR-процессом (проверено выше);
- **внесение в индекс** переходит в `RM-GOV-005`, где правки канона выполняются под
  owner gate `canon_change`.

До этого момента ADR-020 по собственному правилу `AGENTS.md` формально не канон.
Это состояние объявлено и печатается гейтом на каждом прогоне, а не подразумевается.

## 6. Три предсуществующих конфликта самого индекса

Найдены при проверке «без конфликта». Ни один не вызван ADR-020; все измерены, а не
оценены на глаз.

| Конфликт | Факт |
|---|---|
| Два диапазона ADR | `docs/architecture/README.md` объявляет `ADR-001..ADR-015`, `AGENTS.md` — `ADR-001..ADR-019` |
| ADR вне индекса | ADR-018 и ADR-019 есть на диске, но отсутствуют в Active-таблице README. По правилу «никакой файл вне индекса не канон» они формально не канон — при том что **ADR-018 задаёт модель арендатора, на которую опирается `RM-STAB-003`** |
| Баннер против таблицы | 34 документа верхнего уровня в `docs/architecture/` несут баннер `SUPERSEDED`; Superseded-таблица README перечисляет 10. Расходятся 24 |

Все три требуют правки канона, то есть закрываются в `RM-GOV-005`. Пока они не
закрыты, гейт печатает каждый из них на каждом прогоне как объявленное расхождение:
baseline остаётся зелёным, но дефекты не спрятаны, а поимённо названы в выводе.

Отдельно отмечу методику: предыдущий мой подсчёт по этому же файлу был ошибочным —
я считал строки обеих таблиц одним `grep`. Здесь таблицы разделены по заголовкам,
баннеры прочитаны из файлов, а не из README.
