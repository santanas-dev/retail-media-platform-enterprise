# RM-GOV-003 — mini-design: односторонний генератор проекций roadmap

**Статус:** реализовано, ожидает приёмки владельца
**Задача:** `RM-GOV-003` (этап G, зависит от `RM-GOV-001`, `RM-GOV-002`)
**Base SHA:** `2b935bb980028a3e67db51718377836bb6242da9`
**Утверждённая приёмка:** deterministic generation; повторный run даёт clean diff; обе XLSX
sheets и формулы проверены.

---

## 1. Границы владения

| Артефакт | Владелец | Роль |
|---|---|---|
| `docs/product/roadmap.yaml` | `RM-GOV-001/002` | SSOT последовательности работ |
| `docs/product/feature-registry.yaml` | product (человек) | SSOT функционального статуса |
| `tests/ui-smoke/ci-subset.txt` + `tests/ui-smoke/*.py` | CI | evidence: что реально закреплено |
| `docs/product/generated/*` | `RM-GOV-003` | проекции, только для чтения |
| единственный CI-entrypoint governance | `RM-GOV-004` | по правилу B-3 |

Генератор **не регистрирует блокирующий CI-job**. Он предоставляет
`--check-clean-diff` как независимо вызываемый модуль; оркестрацию берёт `RM-GOV-004`.
Это то же правило, по которому `RM-GOV-001` отдал schema-validation модулем.

## 2. Односторонность — как она доказана, а не заявлена

Перед генерацией снимается sha256 всех входов и защищённых файлов
(`roadmap.md`, `roadmap-s020-2026-07-10.xlsx`, `feature-registry.yaml`,
`PROJECT_STATE.md`, `AGENTS.md`), после — сверяется. Расхождение даёт `ONE-WAY` и exit 1.
Проверка входит в tamper-матрицу отдельным кейсом, поэтому «генератор ничего не сломал»
— это результат прогона, а не обещание в комментарии.

## 3. Детерминизм

Источники недетерминизма и что с ними сделано:

| Источник | Решение |
|---|---|
| Часы (`docProps/core.xml`, заголовки zip) | все W3CDTF-метки заменяются на константу; `date_time` каждой записи zip фиксируется |
| Порядок записей zip | записи пишутся в отсортированном порядке |
| Порядок словарей / множеств | все проходы отсортированы явно; `PYTHONHASHSEED` не влияет |
| Локаль, часовой пояс | форматирование не использует locale-зависимые функции |

Доказано прогоном в двух процессах с `PYTHONHASHSEED=1/999`, `TZ=UTC` / `TZ=Asia/Vladivostok`,
`LC_ALL=C` / `ru_RU.UTF-8`: sha256 всех трёх артефактов совпал байт-в-байт.

## 4. Правило «не выдумывать»

Registry доказывает **достижимость** (`reachable`/`blocked`), а не **зрелость**.
Уровни `stand_verified`, `walkthrough_ok`, `pilot_ready`, `production_ready`
не выводимы ни из registry, ни из ci-subset — их ставит владелец.

Поэтому колонка «Зрелость» читается **только** из необязательного блока `maturity`
в `roadmap.yaml` (слот определён схемой `RM-GOV-001`). Блок сейчас намеренно пуст, и
проекция пишет `не заявлено`, а не `0`. Отдельный кейс tamper-матрицы падает, если в
проекции появится уровень лестницы при отсутствующем блоке `maturity`.

Это прямое следствие OD-001: документ описывает требуемое, прогон — фактическое; молчание
входа не превращается в утверждение о факте.

## 5. Формат XLSX

Имена листов сохранены (`Технический Roadmap`, `Бизнес-функции Roadmap`), состав колонок —
новый, потому что проекция строится из SSOT, а не из legacy-строк: 145 из 164 legacy-строк
уже получили диспозицию `history` в манифесте `RM-GOV-002`.

Формулы: в сгенерированной книге **0**, в каноническом `roadmap-s020-2026-07-10.xlsx` тоже **0**
(проверено на уровне XML, а не через `data_only`). Все значения литеральные, вычисляемых
ячеек нет ни там, ни там — приёмочный пункт «формулы проверены» закрыт этим фактом,
а не переносом формул.

## 6. Последствия, которые задача создаёт для следующих

Названы здесь, а не оставлены на обнаружение при cutover.

### 6.1 `roadmap-consistency-check.py` становится тавтологией

Существующий guard сравнивает registry с **вручную** ведомой книгой через
жёсткую карту `UI_SERVICE_MAP` и ключевые слова. Если книга генерируется из registry,
направления A/B не могут расходиться по построению. После cutover этот guard перестаёт
доказывать что-либо и должен быть заменён структурным guard'ом `RM-GOV-004`, а не
переключён на новый файл.

### 6.2 165 из 322 строк `roadmap.md` не воспроизводимы генератором

Манифест `RM-GOV-002` дал диспозицию строкам XLSX (`source_files` — только книга).
Проза `roadmap.md` диспозиции не получала. Непокрытые разделы:

| Раздел | Строк |
|---|---|
| UX backlog — PORTAL-UX-POLISH (аудит A0), включая чеклист ручного прохода | 121 |
| Честные проценты (методика раздельная) | 16 |
| Технические направления | 15 |
| Бизнес-карта по ролям | 13 |

Прямая замена `roadmap.md` проекцией в `RM-GOV-005` потеряет этот материал.
Требуется решение владельца: перенести во входы, вынести в отдельный документ или
дать диспозицию `history`. Это вход в `RM-GOV-005`, не дефект генератора.

### 6.3 Дефект в каноне, найденный сверкой

`roadmap.md` в разделе «Сводка (посчитано программно)» заявляет
`backend/service без UI-journey: 10`. Собственный заголовок раздела того же файла говорит
`— 13`, registry даёт `service = 13`. Число 10 не воспроизводится ничем.
Раздел помечен как посчитанный программно, но расходится с источником — ровно тот класс
дефекта, ради которого вводится генератор. Канон в этой задаче не правится (Gate G);
исправление наступает автоматически при cutover.

### 6.4 Tamper-набор существующего guard'а красный на `develop` — найдено этой сверкой

`python3 scripts/tamper-test-roadmap-guard.py` даёт `3 passed, 1 failed` на чистом
`HEAD 2b935bb` (воспроизведено на `git archive HEAD` без моих файлов — дефект не мой).

Падает кейс `Overclaim (approval Итог=✅ without smoke)`. Корневая причина — устаревшая
фикстура, а не дефект guard'а: кейс ставит строке «Согласование кампаний (Approval)» полный `✅`
и ждёт нарушения, но `campaign.approve` и `campaign.reject` с тех пор стали `reachable`
с зелёными смоуками в `ci-subset`. Подстановка перестала быть ложью, guard корректно
отвечает `clean`.

Последствие реальное: **направление OVERCLAIM не имеет живого доказательства** с момента,
когда эти функции закрылись, и tamper-набор всё это время красный. Это ровно тот класс
«зелёный гейт, который ничего не доказывает», ради которого вводится `RM-GOV-004`.
Кейс должен быть перевыбран на функцию, которая действительно `blocked`, внутри
`RM-GOV-004`; здесь он только зафиксирован.

## 7. Отклонения от утверждённого кандидата

Одно. Приёмка формулируется как «обе XLSX sheets и формулы проверены», что предполагает
наличие формул. Формул нет ни в одной из книг. Пункт закрыт проверкой факта их отсутствия
на уровне XML в обеих книгах; переносить или изобретать формулы генератор не стал.
