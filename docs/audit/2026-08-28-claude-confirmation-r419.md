## 1. Счёт REQ — Codex прав, отзываю «90»

В §25 **101** уникальное требование: 17 BIZ, 11 V26, 2 registry-derived, 71 технических.
Мой шаблон `REQ-[A-Z]+-\d{3}` не мог совпасть с `REQ-V26-*` — префикс содержит цифры.
Тот же класс ошибки, что с бесточечным `observability`: шаблон структурно исключал целое
семейство ID. Воспроизводимо: `grep -oE '\bREQ-[A-Z0-9]+-[0-9]{3}\b' | sort -u | wc -l` → 101.

Покрытие story/scenario: **54 без AP-story**, из них Codex засчитывает один за `SC-ARCH-001`
→ **53/101**. Мой `SC`-парсер не нашёл REQ в строке реестра `SC-ARCH-001` (колонка пуста;
связь есть только в примере §37) — расхождение в одной единице, несущественно. Рабочее число:
**53 из 101 требований не имеют ни story, ни сценария приёмки.**

DEC-014 понижен до «owner decision required» с записью в `roadmap.yaml` — верно.
