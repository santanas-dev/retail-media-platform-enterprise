## 6. Финальная схема roadmap и RACI

### 6.1 Источники

```
                    ┌─────────────────────────────┐
   владелец ───────▶│  docs/product/roadmap.yaml  │  SSOT последовательности
                    │  приоритет · волны · зави-  │  RM-BIZ / RM-TECH / RM-GOV
                    │  симости · решения · gates  │
                    └──────────────┬──────────────┘
                                   │  generator (односторонний)
              ┌────────────────────┼────────────────────┐
              ▼                    ▼                    ▼
        roadmap.md           roadmap.xlsx         counts / метрики
     (человеческий вид)      (бизнес-вид)        (только по формуле)
              ▲                    ▲                    ▲
              └──── read-only · ручная правка = красный guard ────┘

  Не дублируется, живёт отдельно:
    feature-registry.yaml → статус функции     PROJECT_STATE.md → текущий workstream
    user-journeys.md      → спецификация journey    ADR → архитектура
    код / тесты / CI      → фактическое поведение (Tier 1, выше всех)
```

Одновременно с введением SSOT: `roadmap-maintenance-rules.md` → superseded;
`pre-pilot-journey-plan.md` → историческим без активных `Next`; индекс `AGENTS.md` перечисляет
**ровно один** источник очерёдности.

Guard расширяется на то, чего сейчас не покрывает (R7): технический лист и его словарь,
дрейф сгенерированных файлов, нормативность `user-journeys.md`, семантику UI-smoke,
maturity-переходы, единственность канона.

### 6.2 RACI

| Артефакт / решение | Отвечает (R) | Утверждает (A) | Консультирует (C) | Информируется (I) |
|---|---|---|---|---|
| Бизнес-результат, приоритет, волна, scope | владелец | владелец | Codex | Claude |
| Архитектура, acceptance-критерии | Codex | владелец | Claude | — |
| Реализация, тесты, SHA, CI, stand evidence | Claude | **Codex — `ACCEPT`/`REJECT`** | Codex | владелец |
| Канонический статус в репозитории | Claude (после `ACCEPT`) | владелец — для business/pilot/prod gates | Codex | — |
| Производные поля и counts | generator | CI (guard) | — | все |
| Operator walkthrough | человек | владелец | — | агенты |
| Merge · release · deploy | — | **только владелец, поштучно** | — | агенты |

**Два правила предлагаю записать явно:**

1. **Автор артефакта не подписывает его аудит.** Сегодняшний день это подтвердил: я аудировал
   код, который писал Claude Code, и пропустил C1, C2, C6 — их нашёл Codex. Правило должно
   распространяться и на сами аудиты: Claude не принимает свой, Codex не принимает свой.
2. **Ни один агент не правит сгенерированные файлы руками** и не повышает `pilot_ready` /
   `production_ready` — это gates владельца.
