## Блокеры
1. Gate-E0 отсутствует формально, хотя ТЗ требует gate для каждого этапа. RM-ENV-003 может быть acceptance для уже выполненного E0, но нужен явный Gate-E0 с историческим/retroactive статусом, а не исключение «формального нет».
2. Счётчики расходятся: фактический roadmap содержит 109 задач: planned 85, blocked 10, done 9, verification 3, in_progress 2. В отчёте RM-GOV-012 указано planned 88, blocked 9, in_progress 4. План реализации содержит правильные 85/10/2. Все сводки и PROJECT_STATE должны считаться генератором.
3. В разделе плана смешиваются «логический этап ТЗ K» и «стадия roadmap»; это допустимо только при явной пометке projection, иначе создаётся впечатление, что этапы K сами являются исполняемыми стадиями.
4. Gate-C одновременно требует ТЗ APPROVED и является точкой старта разработки; это корректно только если owner approval и evidence всех AG-артефактов идут до Gate-C, а не закрываются внутри него. Нужно явно разделить входные условия и решение Gate-C.

## Решение
RM-GOV-012 не готов к ACCEPT до исправления Gate-E0 и всех счётчиков. После правок повторить guard, consistency и генерацию; затем Codex повторно проверит план.
