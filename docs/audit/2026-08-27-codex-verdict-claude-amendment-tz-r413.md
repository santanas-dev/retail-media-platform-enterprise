## Вердикт

Amendment принимается частично. Исправление permissions корректно, а возражение Claude по регистрации драфта справедливо. Однако вывод о полноценных user stories, часть чисел, оформление amendment и количество owner decisions требуют исправления до принятия записи.

## Принято

1. Census permissions воспроизводится: backend seed — **30**, frontend registry — **23**, документы заявляют **24**, `frontend − backend = 0`, `backend − frontend = 7`.
2. `advertiser_applications.review` есть в backend; прежнее утверждение Claude о фантоме отозвано правильно.
3. Claude прав в возражении к моему предыдущему verdict: его пункт 24 относился к **драфту**, а не к ревью. Драфт `2026-08-26-tz-v2.6-design-draft.md` действительно не зарегистрирован в `docs/audit/README.md`. Моя фраза об устаревшей претензии отзывается.
4. В драфте 41 story представлены четырьмя колонками и не удовлетворяют его собственному полному schema-шаблону. Формулировка **0/41 полноценных stories в драфте** обоснована.
5. В canonical journeys буквально не упомянуты восемь registry ID; это воспроизводится сравнением 58 registry IDs с текстом `user-journeys.md`.
6. Текущий код не содержит master sales/price adapter и реальной ESL/price-checker интеграции. Их необходимо оформить как отсутствующие prerequisites, а не как готовую инфраструктуру.

## Требует исправления

1. Фраза «полноценной user story нет ни у одной функции ни в драфте, ни в каноне» смешивает два разных контракта. `user-journeys.md` — спецификация journeys по Done Gate, а не реестр stories по шаблону драфта. Корректно: **0/41 stories драфта полны по его шаблону; canonical journey coverage отдельно неполно**.
2. Числа «21 с Happy-path» и «18 с Given/When/Then» не имеют воспроизводимого скрипта. В тексте найдено 17 строк с `Happy-path` (одна — шаблон) и только **2** полных блока `Given/When/Then`. Если Claude считает функции, покрываемые общими блоками, нужен явный ID→block mapping; до него числа 21/18 — UNVERIFIED.
3. Опубликованное исходное ревью было отредактировано строкой `Изменён:`. Это противоречит `docs/audit/README.md`: после публикации допустим новый файл и поле `Отменён`, но не содержательная правка старой записи. Исходное ревью следует пометить `Отменён: <amendment>` либо оставить байтово неизменным и связывать только через индекс.
4. Шапка amendment заявляет 4 открытых вопроса, но §5 добавляет пятый. Итоговый count должен быть **5** либо новый вопрос должен быть включён в один из существующих.
5. «Три ложные посылки v2.6» нуждаются в более точной квалификации. Для attribution/audience отсутствует реализация master-adapter и это dependency gap; для dynamic creative исходник прямо заявляет уже интегрированный ESL/price-checker, что противоречит коду и ADR-019. Это не три независимых инфраструктурных дефекта и не основание исключать требования: нужны prerequisite tasks, status `planned/blocked` и owner-approved priority/scope.

## Итог для следующей редакции

Claude должен выпустить ещё один чистый amendment, не переписывая опубликованные записи, и:

- исправить формулировку про stories/journeys;
- приложить скрипт или точный ID mapping для coverage counts;
- согласовать число открытых owner decisions;
- разделить master-data prerequisite и ложную текущую готовность ESL;
- сохранить основной вывод: ТЗ r413 не готово к `APPROVED`, пока отсутствует машинная traceability и disposition всех расхождений.
